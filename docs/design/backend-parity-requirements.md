Research date: 2026-11-17. **Requirements only; no implementation or parity certification.**

UI, running apps, real audio, branches and publication are outside this research assignment. The sole research deliverable is this document. Completion means a sourced, actionable acceptance matrix; passing the matrix requires implementation and separate evidence.

## Acceptance matrix

All rows inherit the shared production gate below. Implementations should identify supported subsets precisely, with structured diagnostics for everything outside them.

### 1. Repeated standard/custom values and exact preservation

**Facts:** Vorbis comments permit repeated case-insensitive names and UTF-8 values. [Xiph comment specification](https://xiph.org/vorbis/doc/v-comment.html) ID3v2.4 ordinary text frames permit NUL-separated values, whereas TXXX has its own description uniqueness and value rules; v2.3 specifies slash-separated lists for certain fields, not a universal punctuation rule. [ID3v2.4 §§4.2, 4.2.6](https://id3.org/id3v2.4.0-frames), [ID3v2.3 §4.2](https://id3.org/id3v2.3.0) Lofty APE appends text values using NUL and replaces values of incompatible types. [APE implementation](https://docs.rs/crate/lofty/0.25.5/source/src/ape/tag/mod.rs) Mp3tag has separate MP4 multiple-data-atom and per-value-atom policies. [Advanced options](https://docs.mp3tag.de/customization/options/tags/advanced/)

| Requirement | Acceptance evidence |
| --- | --- |
| Carry ordered typed values through reads, working state, command boundaries, previews/diffs, recipes, caches, serialization, journals, recovery and Undo. Distinguish absent, one empty value, several empty values and removal. Retain literal semicolons, slashes, backslashes, commas, leading/trailing spaces and Unicode without automatic splitting. | Standard and custom fields with `['A;B','C','C','']` survive save/reload and restart/Undo wherever the target writer supports that shape. Unsupported distinctions fail preflight with field/container/reason; never silently join or drop them. |
| Define capability per **container + tag version + field/value kind**, including language/description/owner qualifiers. Keep opaque/binary items separate from editable text. Retain raw identities when canonical names collide. | Tests include mixed-case Vorbis names, qualified comments/lyrics, custom TXXX/freeform atoms, APE binary/text collisions and numeric-only fields. No generalized TXXX list promise without writer/interoperability evidence. |
| Migrate historical scalars as historical scalars using the original schema/separator policy, rather than guessing new lists. Preserve unchanged native items; define semantic versus byte-exact guarantees. | Old settings/session/journal fixtures replay identically. Untouched unknown frames/atoms, artwork and chapters survive unrelated edits; encoded media payload hashes remain equal. Byte-exact Undo requires original-byte restoration or explicit equivalent evidence, not reserialization alone. |
| Keep split/merge/dedup deliberate, scoped operations; retain first occurrence/order for exact dedup, separately versioning any future case-insensitive mode. | Punctuation inside a single value remains intact. Limits count values **and** bytes across before/after/Undo copies. No-op operations produce no phantom changes. |

### 2. Embedded artwork processing and patterned export

**Facts:** Mp3tag adjusts JPEG/PNG/original format, quality, minimum/maximum dimensions, proportional/square scaling and centered square crop. [Adjust Cover](https://docs.mp3tag.de/actions/adjust-cover/) It supports picture reorder, with format-dependent types, and property keep/clear semantics. [Manage Covers](https://docs.mp3tag.de/manage-covers/), [Set Cover Properties](https://docs.mp3tag.de/actions/set-cover-properties/) Its cover export uses patterned names, MIME-derived extensions, type filters and duplicate-cover options. [Export Cover](https://docs.mp3tag.de/actions/export-cover/) ID3 APIC defines types 0x00–0x14, descriptions and icon constraints. [APIC §4.14](https://id3.org/id3v2.4.0-frames)

| Requirement | Acceptance evidence |
| --- | --- |
| Represent exact raw picture type, description, MIME, bytes and sequence; target by stable identity plus content fingerprint, not a collapsing front/back/other enum. Property-only changes must not decode/recompress. Preserve every untargeted image. | Front/back/leaflet/fish/logo/icon pictures and duplicate bytes with different descriptions round-trip; Apply/Undo restores properties, bytes and order. Validate APIC descriptor/icon constraints before writing. Reject unsupported MP4 type/description requests explicitly. |
| Specify operation order, crop coordinates/rounding, upscaling policy, filter, alpha-to-JPEG background, orientation and color-profile handling. Original-format no-op keeps original bytes; unsupported input codec can remain opaque/exportable without being transformable. | Portrait/landscape/odd-size/tiny/transparent fixtures have asserted dimensions and pixel expectations; JPEG quality is checked as lossy output, not byte identity. EXIF orientation, ICC and malformed images get documented policies and fixtures. No claim of animation/profile retention from generic re-encoding. |
| Pattern export chooses pictures by index/type, adds MIME-correct extension and disambiguates multiple matches. Define duplicate comparison by content plus destination; same name/different content is a conflict. | Sanitization cannot turn distinct names into silent overwrites. Traversal, links, reserved filenames, identical/different duplicate covers, disk-full and cancellation are tested through guarded output publication. No audio changes from export. |
| Bound input bytes, pixels, dimensions, decoded channels/bit depth, transform scratch space, output bytes, picture count and aggregate concurrent work. Cache by image digest + ordered transform options + codec/version. | Huge-dimension compressed bombs fail before allocation; cancellation between decode/transform/encode publishes no partial preview. Evict by charged bytes, invalidate after cover mutation/Undo; no retained decoded full-library cache. |

### 3. Quoted CSV/TSV mapping

**Facts:** Mp3tag documents positional and filename/path-matched pattern imports and a simple comma-separated example; that page does not establish a full multiline quoted-CSV parser. [Text import](https://docs.mp3tag.de/converters/import-tags-from-text-files/) RFC 4180 documents quoted commas/newlines, doubled quotes, optional headers and significant spaces. It is Informational, and does not define a quoted TSV dialect. [RFC 4180 §2](https://www.rfc-editor.org/rfc/rfc4180)

| Requirement | Acceptance evidence |
| --- | --- |
| Adopt RFC-style CSV parsing plus an explicitly documented tab-delimited dialect. Expose delimiter, quote, header and encoding choices in native options; keep existing pattern import semantics stable. Parse logical records rather than splitting physical lines. | Embedded comma/tab/newline, doubled quote, CRLF/LF, final record without newline, trailing empty column and BOM fixtures; malformed quotes/widths/duplicate headers yield record/line/column diagnostics. No silent trimming. |
| Map columns by index or unique header to canonical fields or explicit value indexes; distinguish missing column, empty cell, clear and skip. Multiple columns may form a list only under explicit mapping. Apply locks and container validation. | Empty-policy fixtures prevent accidental erasure. Reject duplicate destinations and conflicting aliases; typed numeric fields reject invalid values. Preview reports all ignored/unmatched/ambiguous rows and files. |
| Preserve sequential, filename and full-path matching against the explicit selection. Never let imported paths authorize filesystem access; ambiguous basenames/duplicate assignments fail. | Different folders sharing basename, case-sensitive versus insensitive filesystem behavior, duplicate keys, outside-selection paths and surplus rows tested. No formula execution or external spreadsheet invocation. |
| Stream bounded records with ceilings for raw bytes, field length, records, columns, decoded bytes and resulting stage/Undo size. | A single unterminated quoted record cannot consume unbounded memory; cancel during parsing/matching leaves the previous stage intact. Compiled mapping cache keys include dialect, schema, encoding and mapping revision. |

### 4. M3U/M3U8 loading and expression grouping

**Facts:** Mp3tag supports M3U and UTF-8 M3U8, loads referenced files in playlist order while omitting duplicate references, and partitions generated playlists using expressions. [Playlists](https://docs.mp3tag.de/playlists/)

| Requirement | Acceptance evidence |
| --- | --- |
| Resolve relative entries against the playlist directory, retain first-occurrence order, and report duplicates/missing/unsupported entries. M3U8 uses strict UTF-8; legacy M3U requires an explicit decoding policy. Define comments/EXTINF, BOM and newline handling. | Unicode, spaces, `#` in path policy, absolute paths, CRLF, duplicate relative/absolute references and missing files fixtures. Distinguish load errors from a valid empty playlist. Loading does not erase pending stage or Undo history. |
| Define native path versus URI grammar; reject unsupported remote/HLS/nested playlists with diagnostics. Do not fetch network entries merely because an M3U8 extension also occurs in streaming contexts. | URL, `file:` URI, Windows drive/UNC on non-Windows, traversal and symlink fixtures. File access remains within granted scope; nested-file recursion is either refused or cycle/depth bounded. |
| Group by the complete evaluated expression over staged values, retaining input order within each group; separately render output path. Define missing group key and alias/list conversion. | Same album with different artists/discs, nonadjacent same keys, empty keys and sanitized-name collisions produce deterministic groups. Proposed path changes generate playlist references from the declared planned/saved path snapshot. |
| Bound playlist bytes/entries/groups/output size; cache parse by content identity and encoding, grouping by selection/order and stage/expression revision. | Cancellation publishes no partial load/preview; grouped write failure reports which outputs exist and can be recovered. Playlist generation does not imply an audio Undo transaction. |

### 5. Reusable reports, encodings/BOM and append

**Facts:** Mp3tag export configurations are reusable text templates with sorted loops, optional loop limits, variables, expression partitions, append and ANSI/UTF-8/UTF-16 encoding/BOM options. [Export documentation](https://docs.mp3tag.de/export/)

| Requirement | Acceptance evidence |
| --- | --- |
| Introduce a bounded template AST: literal text, field/value access, explicit loops/groups, group/file variables and aggregates. Specify ordering, variable lifetime, missing values and numeric overflow. Totals are an app design extension, not established by the cited loop documentation. | Nested album/disc reports, repeated group keys, totals, empty selection, stable tie ordering and list formatting have golden outputs. Reject unclosed loops, invalid scope and unknown directives before publication. |
| Separate text rendering from CSV/XML/HTML escaping; provide explicit escaping helpers and safe built-ins. Arbitrary plain templates remain plain text. Cache compilation by template/version and function/mapping revision. | Quotes, markup characters, newlines and non-BMP characters round-trip through an independent parser for each advertised structured output. Group count, nesting, iterations, expanded text and encoded-byte limits are enforced. |
| Define portable encoding labels, explicit legacy codepage (never unspecified host “ANSI”), UTF-8/UTF-16 endianness and BOM rules. Use strict conversion; state newline policy. | Byte-level fixtures verify UTF-8 with/without BOM and UTF-16LE/BE, surrogate pairs and unmappable legacy text. The encoding_rs UTF-16 limitation above has a regression test. |
| Append means guarded replacement of old bytes + newly encoded bytes, not unchecked in-place append. Verify existing encoding/BOM; write a single BOM only at file start. Declare header/newline behavior and reject incompatible encodings. | Existing output is fingerprinted, copied/streamed into a same-filesystem candidate, checked again before publication and atomically replaced where supported. Test concurrent modification, disk-full, permission failure, cancel, crash before/after rename and retry without duplicate appended content. Bound final target size as well as new content. |
| Explicitly separate output recovery from audio Undo. If reversible exports are promised, journal original target bytes/existence and refuse Undo after external changes. | Multi-group partial publication has durable per-output outcomes; existing output is never deleted by a blind cleanup. Cross-platform replacement/durability evidence is required before claiming atomic append. |

### 6. Composed recipes and encoding repair

**Facts:** Mp3tag offers ordered reusable actions and saves as actions run; export and playlist actions execute after other actions regardless of their listed position. [Actions](https://docs.mp3tag.de/actions/), [Export action](https://docs.mp3tag.de/actions/export/), [playlist action behavior](https://docs.mp3tag.de/playlists/) Convert Codepage repairs selected legacy-encoded fields. [Convert Codepage](https://docs.mp3tag.de/actions/convert-codepage/)

| Requirement | Acceptance evidence |
| --- | --- |
| Define one typed recipe plan covering metadata, encoding repair, artwork, paths and output intents. Evaluate enabled edits sequentially over current staged values. A later step sees only changes permitted by locks and previous successful steps. | Fill Album Artist → repair text → normalize list → crop cover → rename → report/playlist fixture demonstrates exact inputs for every step. Reordering/disabling changes the result predictably. Current extraction mismatch semantics remain versioned and explicit. |
| Adapt immediate-save behavior into preview then Apply. Choose an explicit output phase: recommended outputs run after successful media Apply using the committed snapshot; optional “export planned values” is separately labeled and bound to that plan revision. | No I/O mutation in preview, including output generation. Apply failure prevents dependent publication. Export failure after successful tags reports tags as applied and outputs failed; it cannot pretend SQLite or audio Undo rolled back external outputs. |
| Encoding repair distinguishes decoding original bytes from reversing mojibake in already decoded strings. Specify source/assumed encoding, destination Unicode, strict errors and selected fields; do not repeatedly repair every string heuristically. | Cyrillic/Western codepages, correctly encoded text, mixed fields, malformed bytes and unmappable reversal fixtures. Raw-byte operations invalidate/rebase if earlier steps changed their source field; strict loss detection precedes Apply. Undo restores original content/raw baseline. |
| Plan identity includes ordered steps, settings/mapping/source versions, selected file identity, staged revision and dependent sidecar/image hashes. Freeze random/time inputs if allowed. | Stale stage, changed file, changed image/sidecar or edited recipe rejects/repreviews. Cancel between steps leaves the original stage; cancel during Apply uses existing rollback/recovery journal. Deduplicate shared reads without losing per-file diagnostics. |

### 7. Individual values, enumeration, aliases and filename rearrangement

**Facts:** Mp3tag has zero-based `$meta(field,n)`, all-value `$meta`, `$meta_sep`, and `$list` enumeration; arithmetic is integer-based. [Scripting](https://docs.mp3tag.de/scripting/) Its canonical mappings and user mappings differ: user mappings translate internal names on read and reverse on write, and many sources to one target may write all sources. [Field mapping table](https://docs.mp3tag.de/mapping/), [user mappings](https://docs.mp3tag.de/customization/options/tags/mapping/) Direct filename rearrangement captures up to nine parts and renders them without first writing tags. [Filename–Filename](https://docs.mp3tag.de/converters/rearrange-filenames/)

| Requirement | Acceptance evidence |
| --- | --- |
| Add typed list indexing/join/enumeration with explicit missing versus empty and deterministic field order. Define out-of-range behavior, raw versus canonical field naming and enumeration of readable versus editable items. | Standard/custom repeated values, empty lists, missing fields, index 0/last/overflow and delimiter-containing values tested. Limits apply to enumerated/expanded text; expressions never mutate tags as a side effect. |
| Keep current Tagnetic expression semantics stable. Compatibility adapters publish a signature/arity/truth/arithmetic/regex/escaping table, rejecting unsupported constructs rather than matching names alone. | Tests distinguish current decimal arithmetic from imported Mp3tag integer semantics, Unicode character versus byte indexes, missing fields and regex replacement syntax. Clock/locale/timezone dependencies are explicit and preview-stable. |
| Use one versioned canonical resolver across recipes, imports, output patterns and native commands. Distinguish format identifiers, aliases and custom namespaces; retain language/description/owner identity. Detect alias cycles and ambiguous write mappings. | Mapping change invalidates/reloads reads and compiled expressions; pending plans require repreview. Many-to-one reads with different values must report ambiguity or preserve origin, never silently overwrite. Do not adopt Mp3tag's write-all-source behavior without explicit policy. |
| Capture filename components into temporary variables, render a new path, preserve extension unless an explicit safe policy allows change, and reuse collision/sidecar/rename-cycle protections. Never stage invented tags solely to rearrange a filename. | Capture mismatch, ambiguous separators, repeated captures, case-only rename, swaps/cycles, reserved names, Unicode normalization, root escape and sidecar collisions tested. Apply/Undo restores paths and unrelated stage values. |

### 8. Format policies, timestamps, additional containers and chapters

**Facts:** Mp3tag documents independent tag read/write/remove choices and ID3 encoding policies. [MPEG options](https://docs.mp3tag.de/customization/options/tags/mpeg/) Timestamp preservation covers modification time when writing/removing tags. [Files options](https://docs.mp3tag.de/customization/options/files/) Reusing unmodified frames/atoms and editing existing chapter titles are separate advanced features. [Advanced options](https://docs.mp3tag.de/customization/options/tags/advanced/)

| Requirement | Acceptance evidence |
| --- | --- |
| Publish per-container read/write/remove and per-tag coexistence policy. Preserve original tag version/encoding and unrelated blocks by default; conversion/removal are explicit reviewed operations. Treat field locks separately from native read-only flags. Preserve tag date precision and original text unless conversion is explicitly requested; date-only, year-only and timezone-qualified values must not acquire invented components. | Mixed ID3v1/ID3v2/APEv2, WAV INFO/ID3, AIFF text/ID3, unknown frames, replay gain, comments/ratings and custom atoms tested. Unrepresentable values fail preflight under lossless policy. Validate downgrade effects before any write, including ID3 date-frame conversion, leap-day values and precision that the destination cannot retain. |
| Preserve requested filesystem modification time while updating internal generations and content fingerprints. Keep filesystem times separate from tag recording dates and MP4 container creation/modification fields. Do not promise preservation of OS change time. | Same-size edits with restored mtime still invalidate metadata/art/query/duplicate caches and trigger Undo conflict checks. Test external changes with equal size/mtime, filesystem timestamp precision, timestamp-setting failure, restart and Undo on each supported OS. |
| Existing chapter editing needs stable container/chapter identity, target scope and language-aware title updates, preserving times/order/UIDs/hierarchy and global tags. No implicit chapter creation, timeline editing or audio splitting. | Multiple languages, duplicate titles, nested/ordered editions and global versus chapter edits tested as appropriate. Independent container inspection confirms unchanged offsets/timing/media and preserved unknown data after Apply/Undo. Block writes until the chosen backend proves this. |

Container expansion is **dependency work**, not an allowlist task:

Add checked little-endian size/pointer handling; refuse overlap/truncation/overflow. Create/update/remove ID3 while preserving sample bytes, padding and unrelated chunks. Fixtures need zero/missing/invalid pointer and large-file offsets. |

| **TAK; TTA; OptimFROG OFR/OFS:** Mp3tag writes ID3v1/APEv2 for TAK/OptimFROG and ID3v1/ID3v2/APEv2 for TTA; APEv1 is a read/remove compatibility concern. | **Matroska MKA/MKV:** Mp3tag lists tags, chapters and image attachments. Matroska has targeted/nested tags; chapter editions/UIDs form additional structure. [Mp3tag matrix](https://docs.mp3tag.de/file-formats/), [Matroska tags](https://www.matroska.org/technical/tagging.html), [chapters](https://www.matroska.org/technical/chapters.html), [attachments](https://www.matroska.org/technical/attachments.html) | No built-in Lofty backend. Flat string maps cannot faithfully represent every target or nested tag. |
| **WebM:** Mp3tag advertises tags/chapters/image attachments, but WebM is a constrained Matroska profile. [Mp3tag matrix](https://docs.mp3tag.de/file-formats/), [WebM guidelines](https://www.webmproject.org/docs/container/) | No built-in Lofty backend. Establish the allowed writable element subset and actual player compatibility separately; do not infer full Matroska element support from Mp3tag's matrix. Reconcile profile restrictions before enabling attachments/chapters. |
| **M4V and MP4 chapters:** M4V is included in Mp3tag's MP4 family and Lofty's extension mapping. [Mp3tag matrix](https://docs.mp3tag.de/file-formats/), [Lofty FileType](https://docs.rs/crate/lofty/0.25.5/source/src/file/file_type.rs) | Prove safe metadata writes in real audio/video MP4 variants, including `mdat`, sample offsets, unknown atoms, large/fragmented files and protected variants. `ilst` tag support is not proof of chapter-track or chapter-list writing; choose and verify a chapter-capable backend separately. Playback remains an independent capability. |

No metadata-preservation requirement is satisfied by lossy transcoding or a blanket FFmpeg remux. Select a metadata-aware writer, demonstrate preserved encoded media and unrelated structures, or refuse the operation. A tool's ability to decode a codec is not proof that it can safely edit its container.

### 9. Versioned portability, action import and installable sources

**Facts:** Mp3tag can back up settings/configuration into a ZIP. [File menu](https://docs.mp3tag.de/menus/file/) Its developer documentation defines source descriptions, includes, minimum app versions and line/JSON/XML parsing commands. [Web Sources Framework](https://docs.mp3tag.de/tag-sources/development/) The cited action documentation defines behavior but is not a versioned `.mta` serialization specification. [Actions](https://docs.mp3tag.de/actions/)

| Requirement | Acceptance evidence |
| --- | --- |
| Portable settings/recipes use versioned data schemas, stable IDs, explicit expression/mapping versions and declared dependencies. Exclude credentials, machine grants, runtime caches and personal paths by default; export references/requirements instead. | Export→import into a clean disposable profile produces equivalent native behavior. Old six-rule presets migrate unchanged; future/unknown versions fail without replacing existing settings. Duplicate IDs/names have explicit merge/replace policy. |
| Validate entire package before committing installation; bound compressed/uncompressed bytes, files, nesting, paths and template expansion. Stage imports for review, with atomic settings transaction and durable recovery. | Traversal/absolute paths/symlinks, archive bombs, duplicate keys, interrupted writes, locked database and malformed recipes tested. Failed import leaves current settings and Undo history usable; successful import invalidates affected caches/plans only. |

## Shared production, cache and recovery gate

These are acceptance requirements inherited from the [programme](backend-parity-programme.md), expanded for the researched capabilities. They are not assertions that these checks have passed.

| Gate | Required evidence before a backend checkpoint |
| --- | --- |
| Resource ownership | Explicit ceilings for selection, per-file input, aggregate raw/decoded bytes, before/after/Undo state, compiled patterns, group fan-out, encoded output and concurrent jobs. Account for shared blobs once and copies separately. Boundary/overflow/over-budget tests must fail before publishing a partial plan. Existing guide limits are a baseline, not permission to allocate every limit per step simultaneously. |
| Cache correctness | Charge retained bytes and entry count; retain hot entries under pressure rather than clearing all. Key metadata by authoritative file identity/content plus parse/mapping/policy versions; images by digest/transform options; templates by source/language version; previews by full staged revision/order. Invalidate after Apply, Undo, external refresh, changed policies and source/template updates. Test errors are not permanent negative-cache entries. |
| Staleness | Revalidate write baselines and dependent sidecars/output targets at Apply, not only preview. A cache hit or unchanged size/mtime cannot authorize mutation, particularly with timestamp preservation. Test replacement, concurrent external edits and changed settings after preview. |
| Cancellation and concurrency | Poll at bounded work intervals; do not claim cancellation inside a noninterruptible library call. Bound concurrent decodes/parses and discard cancelled results. Preview cancellation preserves the old stage. Applying jobs use journaled rollback/recovery; report partial outcomes accurately. |
| Durability and recovery | Crash/fault injection before and after snapshot, media write, rename, journal commit and output publication. Retain recovery material until independent readback verifies final state. SQLite interruption is not filesystem rollback. Test insufficient disk, permission failure and retry/idempotency. |
| Preservation and Undo | Disposable fixtures only. Preview must leave media bytes untouched. Apply and restart/Undo need independent metadata/container readback, image byte hashes, encoded media payload hashes and path/sidecar verification. Compare raw untouched elements where exact preservation is promised; decoded audio equality alone is weaker than encoded-media preservation. |
| Compatibility | Legacy scalar settings/journals/action rules, malformed/future schemas and recovery of old batches tested. Complete migration atomically or refuse without damaging original state. Storage/service compatibility review remains separate from reusable core behavior. |
| Evidence and platform scope | Record exact commit, locked dependencies/features, commands/results, fixture provenance, independent reader/version and known unsupported variants. Warning-free formatting/Clippy and meaningful tests accompany implementation. OS-specific filesystem/timestamp/replace checks precede platform claims; no native UI completion inferred. |

## Dependency order and unresolved evidence

Recommended order (a design recommendation, not a schedule):

1. Establish shared bounded-work, staleness, cache invalidation and crash/recovery gates; freeze schema and preservation terminology.
2. Complete typed repeated fields and historical-state migration, then canonical identities/mappings and individual-value access. This is prerequisite to broad list parity, reliable templates and portable recipes.
3. Build bounded CSV/TSV mapping and filename rearrangement on that resolver; playlist parsing can proceed independently with explicit path/encoding policy.
4. Add exact artwork identities/properties and processing with container capability checks; add grouped playlists/reports and guarded replace/append output primitives.
5. Compose recipes over these operations with explicit output phase, then versioned settings/recipe packages and conservative Mp3tag translation.
6. Develop missing container backends in parallel only after specifications, writer choices and preservation fixtures exist. Add chapters after container-specific chapter support is proved. Keep unsupported formats explicitly blocked.
7. Add installable metadata sources after package validation, bounded interpreter/network policies and provider-version invalidation exist; curate upstream candidates after integration evidence and compatibility review.

Further evidence is required before any full-parity or production-ready claim:

- **Resolved dependencies:** reconcile requested image/encoding_rs minima with locked 0.25.10/0.8.44 and actual feature unification. Re-run exact-version preservation/security canaries; do not silently pin or upgrade as part of research.
- **Value fidelity:** which exact standard/custom fields and native item shapes can each writer preserve, including ID3v2.3 conventions, TXXX lists, empty values and multiple MP4 atom layouts? Need native writer fixtures and independent consumer results, not generic `Vec` support.
- **Unknown data:** which Lofty conversions/writes retain versus normalize/drop opaque items, unusual encodings, frame flags and untouched atom layouts? Generic remainder preservation is insufficient evidence of byte-exact behavior.
- **Images:** agree orientation, ICC/EXIF, alpha background, no-upscale and original-format policies; verify resolved codec behavior and metadata retention with fixtures. Decide whether byte-exact restoration requires journaling original container regions or whole originals.
- **CSV/playlist/report dialects:** choose empty-cell semantics, quoted TSV dialect, M3U legacy encoding and URI/duplicate policies, template grammar/aggregation scope and append header/newline behavior. Official Mp3tag docs leave several details unspecified.
- **Container blockers:** obtain authoritative TAK/TTA/OptimFROG layout documentation; select maintainable cross-platform DSF/ASF/EBML writers with licensing and preservation evidence. Prove MP4 chapter representations and unsupported/protected/fragmented variants. Resolve WebM profile versus advertised attachment/chapter behavior.
- **Mp3tag interoperability:** obtain authentic versioned `.mta` examples and producer evidence for its serialization; the docs do not provide a complete stable format contract. Define imported regex/function/list/output semantics explicitly. Do not claim arbitrary `.mta`, `.mte` or `.src` compatibility.
- **Service/storage portability:** identify upstream versus fork schema/provider differences, secret storage boundaries and acceptable package trust/update model before integration. Offline fixture success does not establish live provider authorization, quotas or continued service compatibility.
- **Platform durability:** establish atomic-replace and timestamp precision behavior on supported filesystems/OSes, plus crash tests demonstrating how media Apply, output publication and persistent Undo recover independently.
