## Discogs: evidence and limits

The developer page and support format guidelines returned 403. The attempted `discogs/discogs-api-docs` GitHub location returned 404; no authoritative API blueprint was recovered. Discogs' own client documents `q` examples combined with `artist`, `genre` and `type`, including `type='release,master'`; that example does not establish comma-OR behavior for other fields. [Official quickstart](https://github.com/discogs/discogs_client/blob/master/docs/quickstart.md#searching).

Read-only observations, without an Authorization header, token, key or cookies:

| Request to `https://api.discogs.com/database/search` | Observation |
| --- | --- |
| `type=release&label=React&release_title=Bonkers` | HTTP 200; 34 results; default `per_page=50`. Examples included Hixxy & Sharkey – Bonkers on CD and cassette. |
| Same, plus `format=Album` | 0 results. |
| Same, plus `format=Sampler` | 0 results. |
| Same, plus nonexistent `artist` | 0 results. |
| Same, replacing `label` with a nonexistent label | 0 results. |
| `type=release&release_title=Bonkers&format=Album&per_page=1` (no label constraint) | 10 results; first was Nekobed – Bonkers, `CD, Album`. |
| `type=release&release_title=Bonkers&format=Sampler&per_page=1` (no label constraint) | 1 result: Hixxy & Sharkey – Mini Bonkers 2 - The Sampler, M8 Magazine, `Cassette, Mixed, Sampler`. |

The [base request](https://api.discogs.com/database/search?type=release&label=React&release_title=Bonkers), [Album request](https://api.discogs.com/database/search?type=release&label=React&release_title=Bonkers&format=Album) and [Sampler request](https://api.discogs.com/database/search?type=release&label=React&release_title=Bonkers&format=Sampler) are reproducible source links; counts can change. Their narrowing supports conjunctive behavior for these fields, not exact-string equality or general Boolean guarantees. **Do not claim the 34 results include a Sampler:** that was not observed. The intended search must nevertheless preserve any matching samplers rather than silently add Album.

Additional probes used `q=Bonkers&type=release&per_page=1`, setting each of these independently to `zzzzNoSuchResearchValuezzzz`: `title`, `release_title`, `credit`, `artist`, `anv`, `label`, `genre`, `style`, `country`, `year`, `format`, `catno`, `barcode`, `track`, `submitter`, `contributor`. All returned HTTP 200 with zero items. [Example native field probe](https://api.discogs.com/database/search?q=Bonkers&type=release&per_page=1&track=zzzzNoSuchResearchValuezzzz). These are **observed candidate field names**, not a recovered exhaustive specification: negative probes alone cannot prove positive matching semantics, value grammar or every field's meaning. `title` must not be assumed equivalent to release-only `release_title`.

Positive [Album](https://api.discogs.com/database/search?type=release&release_title=Bonkers&format=Album&per_page=1) and [Sampler](https://api.discogs.com/database/search?type=release&release_title=Bonkers&format=Sampler&per_page=1) searches confirm these are native `format` values, distinct from database entity `type`. The inaccessible [official format guidelines](https://support.discogs.com/hc/en-us/articles/360005006473-Database-Guidelines-6-Format) remain the authority for their definitions. Current exhaustive vocabulary, multiple-format AND/OR, maximum `per_page`, search result ceiling and authenticated rate ceiling remain unverified. One unauthenticated response reported `X-Discogs-Ratelimit: 25`; do not promote this observation into a permanent authentication/access guarantee. [Official authentication options](https://github.com/discogs/discogs_client/blob/master/docs/authentication.md).

## MusicBrainz: exact release index keys

The documented release keys are `alias`, `arid`, `artist`, `artistname`, `asin`, `barcode`, `catno`, `comment`, `country`, `creditname`, `date`, `discids`, `discidsmedium`, `format`, `laid`, `label`, `lang`, `mediumid`, `mediums`, `packaging`, `primarytype`, `quality`, `reid`, `release`, `releaseaccent`, `rgid`, `script`, `secondarytype`, `status`, `tag`, `tracks`, `tracksmedium`, `type`. Unscoped terms search the release title. `type` is legacy release-group classification, not an entity selector. [Official release field table](https://musicbrainz.org/doc/Indexed_Search_Syntax#Release).

Use the explicit query `label:"React" AND release:"Bonkers"` for the example. Optionally adding `AND primarytype:album` imposes a real classification restriction; `AND format:CD` restricts media instead. Compilation is a secondary type and can coexist with Album. There is no documented `secondarytype:sampler` in the official type list; do not invent a direct Discogs Sampler mapping. [Indexed syntax](https://musicbrainz.org/doc/Indexed_Search_Syntax), [type definitions](https://musicbrainz.org/doc/Release_Group/Type). This note does not claim a live result count for that MusicBrainz query.

## Beatport: exact search allowlists recovered

The first-party documentation bundle's `availableFilters` declares:

- Releases: `artist_name`, `created`, `label_name`, `pre_order_date`, `publish_date`, `release_type_id`, `upc`.
- Tracks: `artist_name`, `available_worldwide`, `bpm`, `change_date`, `current_status`, `genre_id`, `genre_name`, `guid`, `is_available_for_streaming`, `is_classic`, `isrc`, `key_name`, `label_name`, `mix_name`, `new_release_date`, `pre_order_date`, `publish_date`, `publish_status`, `release_name`, `was_ever_exclusive`.
- Artists: `created`, `enabled`, `updated`. Labels: `enabled`, `is_available_for_streaming`.

The same source defines `q`, `type`, `page`, `per_page`. `q` searches all catalogue fields with name matches prioritised; it is not release-title-only search. Release search does **not** list a separate `name` or `release_name` constraint. Thus `q=Bonkers&type=releases&label_name=React` is a documented search shape, but cannot promise title-only semantics. Source descriptions do not settle exact equality, cross-field AND, comma-OR or numeric/date range grammar. Those require accessible first-party schema/facets and authorised validation. [Official docs source](https://api.beatport.com/static/btprt/cf97cb38488437dfc387.js), [authentication-gated schema](https://api.beatport.com/v4/swagger-ui/json).

## GnuDB: TOC lookup and newer text search

Classic `cddb query discid ntrks off1 off2 ... nsecs` matches CD layout, not artist/label text. Current GnuDB returns server-assigned `gnucdid` identifiers for metadata retrieval; the legacy disc ID/category are compatibility placeholders. [Current GnuDB explanation](https://gnudb.org/).

GnuDB now explicitly documents `cmd=search&artist=bob+dylan&album=New&tracks=4`, returning matching CD entries. This provides evidence for **artist and album text plus a tracks parameter**, not label filtering. The example's `tracks=4` suggests track count; it does not document track-title syntax. AND/OR, optionality, exact/partial matching, pagination and result caps are unspecified. The homepage mentions track-information search, but its endpoint grammar remains unclear. [Developer protocol](https://gnudb.org/howtognudb.php), [homepage](https://gnudb.org/).

Developer guidance prefers HTTP(S), protocol 6; requires meaningful application/version and valid-looking email identification in `hello`, and requests developer contact/registration. No fixed numeric rate quota is published there; misuse can be blocked/rate-limited. The developer page also requires a `cddb query` before `cddb read`; how a text-search-only result satisfies that rule needs clarification before promising the retrieval workflow. [Protocol/access policy](https://gnudb.org/howtognudb.php). No GnuDB API calls or submissions were made.

## Planning consequences and unresolved access

- Keep Label + release title as distinct constraints where supported. Concatenating `React Bonkers` into free text does not satisfy that contract. Default to matching releases without an Album restriction; expose musical type only where its actual provider meaning is established.
- Separate entity selection, musical classification and medium format. Discogs `type=release`, MusicBrainz release-group types and Bandcamp album result categories are different concepts.
- Bandcamp `/api/bcsearch_public_api/1/autocomplete_elastic` and `/api/discover/1/discover_web` are **unverified internal endpoint leads**, not published catalogue API contracts established here. Do not assert their filter names, page caps or auth requirements. The official API documentation does not document them; Discover/browse facets cannot establish public search support. [Published Bandcamp APIs](https://bandcamp.com/developer).
- Soundeo website artist/label facets are documented; reusable search endpoint support is not. Beatport's documented search allowlists are stronger evidence, but schema/access and precise combination semantics remain unresolved.
- Future “freedb” planning must name GnuDB and distinguish TOC lookup from its newer text-search extension. Artist/album have current first-party evidence; label does not. Do not transfer modern GnuDB extension capabilities back onto historical freedb.
