## Other gaps and possible follow-up

- **History-generation consistency and scale.** `SqliteJournal::batch` selects header then calls the loader after the statement has ended, so ordinary detailed reads can still span commits. `headers` also preflights native counts separately from its metadata query. `batches` keeps the initial statement active while loading details, but is a fully hydrated all-history API used by background/internal paths. Review snapshot consistency and durable retention/paged history with two-connection fixtures and large profiles. A read transaction alone does not establish ownership up to the filesystem operation.
- **Long recordings.** The compatibility `ogg_safe_write` snapshots whole files before and after, and `write_iff_id3` currently reconstructs WAV/AIFF bytes in memory. Exact-read calls cap their own compatibility full-file fallback, while those write paths still need proportional streaming/backed staging, independent encoded-tail comparisons and failure injections for hard links, modes, xattrs, disk full and rollback. A user with multi-hour recordings can take more memory on these formats than on a native selective route.
- **Write-failure edge cases.** On the normal direct tag writer, the rare APE misidentification padding repair currently runs before year/rating validation, although plan preflight normally protects interactive writes. A deterministic real-format round trip is needed before reordering all of the compatibility guards. Ogg integrity currently compares a parsed result and final granule value. That guards known shortening cases and is narrower than a proof of packet identity for arbitrary malformed streams.
- **Platform and artifact recovery.** Existing native Windows/Unix tests, Linux process-death fixtures and earlier hosted evidence explain implementation intent. Crash after a guarded output set or a studio source replacement can leave a recovery manifest for inspection. Automatic restart replay is outside the process-local ownership contract. Unknown volume primitives can refuse publication before changes. No physical power-loss, NAS or removable-volume certification was performed here.
- **Scope and infrastructure.** No redundant service or database is needed for the fixes above. A profile's SQLite ledger and existing held-media ownership records already provide the right durability boundaries. Temporary memory pressure and large-profile query/retention warranted targeted measurement before proposing new storage infrastructure.
