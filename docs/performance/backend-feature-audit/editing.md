### Confirmed fix

M3U `#EXTINF` and CUE metadata occupy one line per record. A title or artist containing LF, CR or CRLF previously broke that structure even though the saved metadata itself was valid. The common writer now replaces each logical break with one space only in these display fields. The existing format-specific escaping and path handling stay in place. `playlist_and_cue_metadata_stays_within_its_record_line` showed differing actual and expected output for both formats before this change.

### Verification run

- The baseline regression showed differing actual and expected output for both M3U and CUE before the fix. The focused run recorded 351 passing tests and 6 ignored across core unit, mask property/budget/boundary and report integration suites.
- The combined workspace run verifies command-library behavior, including editing and duplicate scanning.
- Independent binary verification recorded three passing independent disposable-audio round trips covering field recipes, native batch and tabular import. It also recorded a passing independent CSV/XML UTF-8 and UTF-16 consumer check. These ran using the binaries built by the corresponding suites above.
- `git diff --check` passed. The relevant graph paths reported complete index coverage and source reads resolved ambiguous matches before drawing conclusions.

### Remaining evidence

- M3U/CUE source references with newlines and some path punctuation need a defined representability policy. Changing file references without an agreed round-trip would be unsafe. Local playlist loading and strict CUE consumer coverage are separate from metadata normalization.
- Legacy text recipes can build a large transient output inside a chain before the final per-file batch check. A shared streaming transform budget needs throughput and compatibility measurements. The specialized grouped report engine already has separate admitted rendering.
- Platform-sensitive file and output behavior was reviewed in source. Native Windows/macOS file operations, dialogs, and device-specific text consumers are outside this worker's Linux verification.
