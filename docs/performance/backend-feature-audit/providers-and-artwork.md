# Provider and artwork backend feature audit

Reviewed from 1d8ac26e. Direct source checks verified the graph routes for 46 provider, artwork, fuzz, and call-site files. This ledger covers the native desktop providers, their service-facing seams, the 14 documented artwork behaviors, and the four fuzz targets. Tests cited as existing evidence passed in the corresponding baseline or focused run when listed in the logs. Source-only seams and platform or network gaps are called out. No live provider account, token, user library, or real artwork write was used.

## Related infrastructure and evidence gaps

- `cover::pipeline::Processor` is a standalone Rust capability with strict header and decode validation, explicit orientation/rotation/crop/resize options, output/metadata policies, cancellation before publication and shared resource limits. Its three integration targets exercise proportional rounding and explicit upscale policy, strict malformed input, concurrent option and cache pressure, cancellation, independent pixel checks and fresh EXIF/orientation evidence. The desktop has wired `resize_cover` and the webview rotation path. Bringing the separate pipeline into the shipped flow would require compatibility evidence for preserved bytes, role and size/quality behavior across existing formats before switching callers.
- Service equivalents are `providers.status/search/release/release_tracks`, `artwork.fetch/load/upload/read/inspect/embedded/export`, and `draft.artwork`. `DesktopProviders`, `secure_provider_image::fetch`, `artwork_policy` and `outputs` enforce permission, per-redirect HTTPS/DNS checks, public destinations and separate bounded formats/pixels/bytes before making service assets and writing. `rejects_local_reserved_and_tunneled_destinations` and `url_checks_apply_to_relative_redirect_targets_too` exercise policy with synthetic URLs. See the service ledger for handles, receipts, scope and teardown.
- The legacy desktop `read_external_cover` and `read_cover_image_art` read an entire file by extension before encoding. Dedicated service artwork and desktop resize have resource guards that these raw read paths do not share. Separately, desktop `save_release_images` can accumulate multiple individually capped images between its initial target validation and final session/publication check. Harden the shared desktop ingest with bounded read and aggregate queue bytes after normal-use compatibility fixtures for image formats and large files. These shared-source entries lie outside this agent's edit ownership.
- Provider transports bound individual requests and cap pagination, but the longer Beatport aggregate request sequence has no total deadline and cancellation test. A product decision needs latency evidence on representative long releases. No provider database or new service was added. Provider clients, existing image pools and disk outputs already have clear ownership and reuse. Live auth, native browser activation and vendor/CDN drift remain distinct from deterministic parser coverage.
- `fuzz/fuzz_targets/tag_read.rs` loads all tag families and requested technical fields. `tag_write.rs` selects writable tag operations and reads fixtures back. `cover_resize.rs` exercises varying fit size at fixed quality on arbitrary input. `player_decode.rs` exercises probing and full decode. `fuzz/src/lib.rs::run/input_file` distinguish expected contained errors from escaping panics and use reusable per-process scratch files. CI controls the per-input timeout and global RSS budget. Fuzz is a separate workspace with checked-in format seeds and scheduled/manual matrix in `.github/workflows/fuzz.yml`. Source reviewed. No campaign or sanitizer run was performed in this audit.

## Candidate changes

- `crates/providers-bandcamp/src/lib.rs::parse_search` borrows parsed entries while projecting owned candidates. Results, order, missing-field rules and artwork URLs keep the existing contract.
- `parse_release/year_from_date` retain the first valid year from the primary display date, album date or JSON-LD. The new regression `a_release_uses_a_valid_iso_date_when_its_primary_date_is_unusable` failed on the base behavior with `None` instead of `Some(2024)` and also checks ISO timestamps and malformed date prefixes. This preserves precedence when the first field already parses.

## Verification

- Fresh Linux Cargo 1.98.1 run with the shared cache, locked dependencies in offline mode, four test threads and all five provider crates selected. 117 passed, zero failures and one deliberately ignored live Beatport docs lookup.
- The new Bandcamp regression failed against its old implementation, independently reproducing the missing year. The same test passed in the five-provider run. `git diff --check -- crates/providers-bandcamp/src/lib.rs` was clean.
- The exact old and new `parse_search` functions ran in the same synthetic process and crate dependency build. On 250 mixed provider rows, the 84 output candidates matched field for field. Allocation requests including reallocations decreased from 8,106 to 4,355 and requested bytes from 537,527 to 314,997, about 46% and 41% respectively on this input. Malformed JSON, missing arrays, empty arrays and incomplete album entries produced matching results as well. This is an allocation comparison without a typical-response or elapsed-time claim.
- The unchanged standalone artwork integration targets at baseline passed 28 tests with four opt-in independent-readback or diagnostic cases ignored. The wave-one Linux desktop tests passed all six Beatport session lifecycle tests and both secure provider image policy tests. The final integrated workspace run owns cross-feature readback on the candidate.
