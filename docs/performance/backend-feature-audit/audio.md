# Audio Studio, player and media integrations

Audited at `1d8ac26e` plus the media-session fix in `app/src/media_session.rs`. The inventory covers all 25 shipped `audio_split_*` desktop handlers, all eight `player_*` handlers, desktop media and BPM handlers, and five backend feature groups with shared or non-IPC entry points. Source comparisons use the registered handlers in `app/src/main.rs` and cross-reference the audio-studio roadmap, duplicate/listening feature checklist and spectral repair implementation notes.

**Evidence legend.** Linux base means the listed test passed in this audit's isolated baseline on otherwise unchanged audio code. Linux focused means the listed candidate verification ran separately. Gap identifies a missing boundary or an expressly experimental path. All source paths and test files listed below were checked with codebase-memory exact coverage or read directly. Product tests use disposable fixtures. No real music or live profile was opened, and fake, independently decoded or D-Bus transports do not prove playback on a physical output device.

## Findings and disposition

- **Fixed, media session.** A paused/slow artwork read could publish an earlier Playing snapshot after the current Stop/seek or after changing tracks. The original update body deterministically reproduced Playing reappearing after Stop, and the candidate suppressed it. The candidate keeps fresh transport publication independent of artwork I/O, with bounded decode backlog, same-path reentry generations, and original platform publication functions. Native macOS and Windows remain evidence gaps.
- **Performance measurement, not a regression finding.** Audio-only synthetic 12-second AIFF probe under the same build compared a raw fixed converter with a controlled fixed converter. The controlled path preserved the sample checksum. Warm conversion plus checksum medians were 63.137 ms raw and 139.597 ms controlled, seven counted runs. This is CPU work in an isolated fixture with no physical output and no desktop renderer. It motivates profiling control synchronization before any code change. The four-format independent seek proof and CBR/VBR studio loop proof both passed.
- **Open reliability.** Finish the native codec/device/platform matrix. Repeated hotplug/no-output, stop during actual blocked storage, file associations and device callbacks are not established by fake-sink tests.
- **Open resource/performance.** Profile long unindexed compressed input overview under realistic seek offsets and measure fresh start, cancellation, memory, and waveform/spectrogram event timing separately. Workbench bounds decoded windows, FFT columns, and per-segment packet work, but these bounds do not establish a long-file latency objective.
- **Open durability.** Tool-window preferences are cosmetic and fall back to defaults when damaged. The current sidecar uses a temporary rename and no fsync/restart guarantee. The audio replacement completion Undo token is only the retained current export job. Original backup and manual recovery manifest persist. An additional audit of process loss during media output, restart recovery, and switched-session state should use disposable fixtures.
- **Cross-owner registry check.** The desktop uses all eight player registrations, and the service catalog and dispatcher expose six corresponding playback operations. `playback.resume` appears in the desktop adapter only, where the current service dispatcher cannot route it. That distinction is a source-confirmed discoverability gap, not a shipped callable tool. Duplicates, external provider authorization, protected output, settings, and library membership are covered in their owning feature maps.
