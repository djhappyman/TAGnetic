## Open evidence and behavior limits

- On Windows, duplicate-analysis `Stamp` has length and modified time only, unlike the stronger Windows display-cache identity. Native standard and removable-volume fixtures are needed before changing identity or refresh behavior. On all platforms the duplicate cache clears at 4,096 entries, so repeated large-library passes need workload measurement before choosing a replacement policy.
- An external edit to the first stored same-audio cluster leader can suppress matches between later unchanged files until a rerun. Stabilizing progress and group identifiers while selecting a replacement leader needs a targeted product decision and fixture.
- The likely budget limits unique pairs, while repeated probes of the same pair through different tokens still cost CPU. Cancellation is now checked within those probes. The decoded-fingerprint and graph budgets remain matters for representative large-library profiling.

## Executed focused gates

- Linux `cargo test --locked -p tagrex-commands --lib duplicates:: -- --include-ignored --test-threads=4` passed 16 tests, including the previously opt-in FFmpeg-generated cross-encoding fixture, with zero failures or skips.
- An isolated Rust harness using both original candidate loops and the new helper reproduced over-retention and absent inner-loop cancellation before the change. Both checks pass afterward. The original duration-bucket expression also reproduced arithmetic overflow for a finite custom duration, and the new expression returned the two representable neighboring buckets.
- The opt-in `read_cache::tests::shared_resource_cache_pressure_benchmark` passed on 2,500 disposable WAVs. This fixture recorded 99.7 ms cold, 1.9–2.3 ms warm over five passes, and 96.7 ms under retention pressure. These are local fixture timings, with no end-to-end or cross-platform performance claim.
