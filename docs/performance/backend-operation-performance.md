# Backend operation performance

28 November 2026. Baseline `54181f22`. The [feature and endpoint inventory](backend-feature-audit/inventory.md) accounts for the desktop commands, local service tools and shipped workflows. This pass follows those operations through their Rust work, including file I/O, metadata calculation, audio DSP, and preparing results for the interface.

## Before and after

The measurements are native Rust release-profile timings on Linux x86-64, Intel i7-12700K, Rust 1.98.1. Inputs were generated or disposable. Each row names the timed part of the operation. No personal media or live provider account was used.

Write timings use seven alternated samples. The 60-minute WAV ranges were 1,156–1,494 ms before and 169–243 ms after. AIFF was 161–203 ms before and 38–48 ms after. The one-hour MP3 overview used 12 paired samples and ranged 1,412–1,682 ms before and 80–83 ms after. The initial MP3 index analysis took 2.2–2.4 seconds on that fixture and is separate from the overview. Snapshot, text-matching and DTO timings use 11 alternated samples. The 100,000-row second-snapshot range was 5.50–6.89 ms before and 0.0050–0.0081 ms after. That gain covers making a handle over an existing in-memory model. It excludes scanning, sorting and sending page data across the webview boundary. Warm snapshot creation no longer walks 100,000 paths or allocates and increments 100,000 row references.

## Operations and cost boundaries

| Area | Native work and evidence |
| --- | --- |
| Tag conversion, text writes, embedding, removal and compatibility | WAV and AIFF metadata updates seek over sound chunks and patch the changed tail when its layout permits. Interleaved tags still use the general rewrite. Ogg and some legacy operations still retain whole-file buffer or recovery costs. Existing descriptor, tag-block and independent packet tests cover MP3, FLAC, WAV, AIFF, MP4 and Ogg variants. See [native writes](backend-feature-audit/writes.md). |
| Rename, move, sidecars, copy, Apply, Undo, Redo and recovery | Prepared SQLite statements are reused through journal batches. Journal reload uses indexed child-presence checks. Native FLAC intent recording hashes its allowed roots once per batch. Rename, copy, persisted checksums and recovery checkpoints retain their existing ordering and durability. Whole-operation timings depend on the source and destination filesystem. See [native batch operations](native-batch-operations.md) and [move component profiles](backend-staging-cleanup-profile.md). |
| Open, refresh, search, sorts, grouping, suggestions, duplicate and integrity scans | Natural path sort compares digit runs and ASCII text directly with the existing Unicode ordering as fallback. Explicit file-set sessions index membership once while preserving their ordered selection. Full-scope service handles share immutable row vectors. A long duplicate scan retains up to 4,096 useful results within its memory budget, so the measured warm scan only reanalyses 404 files. Exact, same-audio and likely-duplicate modes retain their separate validation rules. Earlier [library queries](library-query.md) and [integrity lookup profiles](metadata-and-integrity-lookups.md) record the filter, suggestion and incremental-update workloads. |
| Editing and transforms | Type conversions, general math and text transforms run in the mask and recipe engines. Masks and technical fields reuse the same metadata read where possible, and numbering borrows saved fields until an overlay requires a copy. Desktop queues coalesce stale previews. Progress, staged overlays, lock checks and explicit file order remain part of the work. See [recipe timings](native-field-recipes.md) and [preview queues](preview-queue-hardening.md). |
| Import, export and front-end data preparation | Filename/text/table/sidecar parsing, numbering, custom columns and report/playlist/CUE generation keep their existing grammar and output formats. M3U reuses the duration from the tag probe, and the output publisher takes ownership of a rendered buffer. Fuzzy matching skips repeated identical comparisons and trims the edit-distance matrix while scoring against the original length. Provider results move parsed strings into DTOs. See [editing, imports and exports](backend-feature-audit/editing.md) and [bounded export rendering](bounded-export-rendering.md). |
| Audio open, waveform, spectrogram, EQ, restoration and playback | The overview reuses its decoder for compatible windows and skips old compressed packets only once when an MP3 lacks a trustworthy index. Rasterization combines only the frequency bins covered by a repair region. Fixed-format playback skips repeated source-format queries with the seek checks in place. Preview and export share DSP and repair code. Active playback meters are derived from the audible sample packets. BPM, EQ reference matching, EQ threshold learning and device latency have their own evidence boundaries. See [audio paths and fixtures](backend-feature-audit/audio.md). |
| Conversion, splitting, replacement and output | MP3/FLAC frame-copy and exact encoding use distinct paths. Four generated split segments totaling 48 seconds measured about 1.5 ms FLAC and 2.0 ms MP3 in the frame-copy writer, with roughly 1.8 ms and 0.1 ms respectively for index preparation. Re-encoding took about 319 ms FLAC and 252 ms MP3. There was no material change in those encode paths. Exact export, treatment, source-format decisions, marker rounding, guarded output and replacement Undo are checked independently. See [output readiness](backend-output-readiness.md) and [media mutation](backend-media-mutation-readiness.md). |
| Provider transport and artwork | Discogs, MusicBrainz, Beatport, Bandcamp and Soundeo retain their per-source pacing/authentication and parser contracts. Image import/rotation, transform, encoding, summary, export and legacy image-write paths use separate fixtures and budgets. Provider conversion evidence isolates local CPU work. Network waiting, full webview image rendering and account flows have separate performance costs. See [providers and artwork](backend-feature-audit/providers-and-artwork.md) and [artwork resource limits](artwork-resource-hardening.md). |
| Desktop shell, IPC, local service and jobs | Desktop command admission, local frame sizes, scope and revision validation, staging deltas, reports, analysis jobs and cancellation retain their existing boundaries. Service snapshots validate immutable row pairing before caching. Native app, platform media controls, and connected-client transport have distinct queues. See [desktop and platform](backend-feature-audit/shell-and-library.md) and [local service](backend-feature-audit/service.md). |

## Concurrency, caching and prewarming

- Linux MPRIS now prepares cover files on the existing bounded blocking worker. A private D-Bus test holds a half-written image while Pause and position reporting still reach the exact requested state. Stale and retired files are dropped outside the report and session locks. Art URLs publish only after a complete write and a matching playback generation.
- The legacy artwork resize cache remembers one recent source under its existing 64 MiB ceiling and shared admission budget. A repeat can reuse the encoded result on immutable identity or exact bytes, with the same requested dimensions and quality. The measured resize used 57 warm samples per build. The cost of reading, downloading and base64-decoding artwork is separate.
- Studio shares already-completed waveform and seek analysis across simultaneous opens of an unchanged source. Each session keeps its own descriptor, treatment state and frame-copy setup. A refused warm open returns its validated source to the existing two-entry recent cache. The seven-sample MP3 probe excludes frontend rendering and starts its active-open test with one session already prepared. Cold-open medians were about 351–363 ms. There is no speculative decode during playback.
- Desktop query and suggestion calls still go through the session queue for acquisition and final version validation. A separate read-only publication of the current generation could avoid two waits while other session work is queued. A useful experiment must delay Apply and policy changes and exercise new library publication, stale cancellation, and hidden selection against that timeline.
- Online search already coalesces thumbnail work and reuses release metadata. Image-client acquisition still waits behind same-source lookups. A prepared client would need to preserve proxy, auth generation, request pacing, and credential lifetime across that wait. Local or fetched service artwork also has an avoidable base64 round trip before validation. Both opportunity measurements are open.
- Next-track decoder preparation still runs on the transport actor. Test one generation-scoped preparation on deliberately slow storage and measure Pause and Seek acknowledgement and continuous next-track playback. Query facets already build and cache on demand. A targeted warmup for an explicitly requested field would need to prove faster first suggestions on 100,000 rows with no loss of playback or query responsiveness.

## Verification

- Linux workspace tests passed 2,178 with zero failures and 50 ignored. Read-only reference tools were required for the independent codec fixture tests. The initial four-thread run failed the recovery-store alias fixture with a lock capacity error. The exact unmodified baseline reproduced that failure with four threads and passed with one. The final combined suite used one test thread.
- Three additional MPRIS tests passed on a private D-Bus session. Workspace formatting and all-target, all-feature Clippy with denied warnings passed. All four fuzz targets compiled in their separate workspace.
- An isolated native Linux Tauri/WebKit run opened two disposable library files, applied and undid a WAV title, and returned 192 distinct left/right spectrogram columns for a one-minute MP3. Two native sessions shared the same overview while keeping different session IDs. Independent FFmpeg packet hashing and FFprobe metadata readback verified the WAV after Undo.
- Independent source review checked the final changes to decoder reuse, DSP, playback, RIFF/AIFF, journal recovery, sorting, matching, cache bounds and Linux media publication. A shared scoped query vector now retains its admission charge even if the parent query handle is dropped.

Timings characterize the measured fixtures and operations. Native Windows and macOS, physical audio-device latency, real webview repaint latency, live provider calls, cold production libraries, and long exFAT or network filesystem writes were outside this gate. The optional background-work ideas above still need those workload measurements.
